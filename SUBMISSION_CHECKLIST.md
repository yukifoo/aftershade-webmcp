# Submission checklist

Live status, maintained during the build.

## MUST SHIP — submission survival

- [x] Official deadline and current rules verified.
- [x] Product selected from 20 scored first-principles concepts.
- [x] Product thesis and 45-second magic moment defined.
- [x] Core human-editable neighborhood state works.
- [x] Deterministic scenario simulation works.
- [x] At least two reversible plan branches work.
- [x] Imperative WebMCP tools register in the top-level page.
- [x] Agent can inspect, mutate, simulate, compare, and recover from stale state.
- [x] Human can interrupt and agent can adapt to the new revision.
- [x] Demo reset restores the exact initial state.
- [x] Production deployment succeeds over HTTPS.
- [x] WebMCP discovery and invocation pass on production.
- [x] Public source repository exists.
- [x] GitHub detects the MIT license.

## SHOULD SHIP — submission assets

- [x] README complete.
- [x] WebMCP tests documented and passing.
- [x] Deployment/reproduction guide complete.
- [x] Devpost submission copy complete.
- [x] Demo script and reset procedure complete.
- [ ] Public YouTube video under 3:00 with narration.
- [ ] Live URL, repository URL, and video URL entered in Devpost.

## CUT IF NEEDED

- [ ] Additional neighborhood presets.
- [ ] Exportable planning report.
- [ ] More than two candidate branches.
- [ ] Decorative imagery or social card.
- [ ] Any external data integration.

## Protected schedule (JST)

- 10:12–10:35 — rules, WebMCP model, ideation, concept lock.
- 10:35–12:15 — core product and first local WebMCP workflow.
- 12:15–13:00 — early production deployment and production tool validation.
- 13:00–14:30 — reliability, collaboration flow, responsive and accessibility fixes.
- 14:30–15:30 — README, submission copy, demo script, red-team, repository publication.
- **15:30 — feature freeze.**
- 15:30–16:25 — record/edit/upload demo; verify every public link.
- 16:25–16:45 — Devpost fields and final submission.
- 16:45–17:00 — protected contingency only.
